# 07 — sse-stream

Живой тикер по Server-Sent Events, на **pull-based**-продьюсере
(`stream_body(fn() -> Option[[]u8])`), а не на заранее собранном конечном
списке чанков — замыкание вызывается по разу на чанк, `None` завершает
поток.

По мотивам: `sse`-пример axum.

## Запуск

```sh
nova build --strict-effects src/main.nv
./main   # слушает 0.0.0.0:18088
```

```sh
curl http://localhost:18088/events
# event: tick
# data: 5
#
# event: tick
# data: 4
# ...
# event: done
# data: bye
```

По реальному сокету драйвер соединения пишет каждый чанк `event:`/`data:`
собственным `write_all` в момент, когда продьюсер его отдал, — настоящая
инкрементальная доставка (см.
[`docs/serving.ru.md`](../../docs/serving.ru.md#потоки-и-sse)). `curl`
выше просто печатает уже полностью слитый ответ, поскольку у тикера нет
искусственной задержки между тиками (см. «что покрутить»).

## Что покрутить

- Замыкание `ticker` намеренно без эффектов (`fn() -> Option[[]u8]`, без
  `Time`/`Net` в сигнатуре — таков тип, который ждёт `stream_body`).
  Настоящий медленный тикер вместо этого блокирует файбер-продьюсер на
  чём-то с реальным эффектом, например `ChanReader.recv()`, питаемом
  отдельным `spawn`-файбером-таймером — см. заметку в разделе про потоки в
  `docs/serving.md` про форму.
- Меняй имя `event` в `sse_event` по тику (`"tick-${n}"`) — и посмотри, как
  клиентский `EventSource` (в браузере) диспетчерит по разным именам
  слушателей.
